# AIRL: воркшоп «Готовый продукт за 1 день»

Лендинг воркшопа и всё, что нужно для его работы: страница, бэкенд заявок,
админка и скрипт установки сервера.

- Страница: **https://airl.kz/ai-for-work/workshop/** (папка `ai-for-work/workshop/` в репозитории
  `aza9908/landing`, публикуется Firebase App Hosting вместе с остальным airl.kz)
- Бэкенд заявок и админка: https://server.airl.kz/api/lead и https://server.airl.kz/admin
  (логин `admin`, пароль в `/etc/airl-workshop.env` на сервере)
- Сервер: 89.35.124.238, Ubuntu 24.04, nginx (там же trainer, kaidzen и pingwin).
  Посетителей самого server.airl.kz он отправляет на airl.kz/ai-for-work/workshop/ (с UTM-метками).
- Прежние адреса: https://airl-workshop.web.app (Firebase, старая форма в Google-таблицу),
  https://server.airl.kz (теперь редирект)

## Что где лежит

| Путь | Что это |
|---|---|
| `site/` | Готовая сборка страницы: HTML, JS, CSS, картинки, шрифты. Копируется с airl-workshop.web.app GitHub Action'ом (см. ниже). |
| `hq/` | Фото в высоком разрешении: вырезаны из оригиналов с телефона с тем же кадрированием, без фильтров и без GPS. При сборке подменяют файлы из `site/` с тем же именем. |
| `airl-head.html` | Теги, которые есть только в версии для airl.kz (Meta Pixel). Сборка вставляет их в конец `<head>`. |
| `build-airl.sh` | Собирает страницу для airl.kz в `dist/airl/`: пути под `/ai-for-work/workshop/`, форма на server.airl.kz, WhatsApp, фото из `hq/`, теги из `airl-head.html`. |
| `app/app.py` | Бэкенд заявок. Python 3.8+, без сторонних библиотек. |
| `app/sitetool.py` | Копирует страницу и готовит её к публикации: адрес формы, номер WhatsApp, подпапка, фото из `hq/`. |
| `install.template.sh` + `build.py` | Исходник скрипта установки. `python3 build.py` собирает из них и `app/*.py` один файл `install.sh`. |
| `install.sh` | Готовый скрипт установки и обновления, один файл. |

Исходного Vite-проекта страницы (папки `src/`) здесь нет: его не нашлось ни в одном
репозитории. В `site/` лежит собранная версия, которая работала на Firebase.

## Как проходит заявка

1. Человек заполняет форму (имя, телефон, город). UTM-метки из ссылки добавляются сами.
2. Страница отправляет заявку на https://server.airl.kz/api/lead.
3. Бэкенд сохраняет её в базу (`/opt/airl-workshop/data/leads.db`) и отправляет:
   - копию в Google Sheet (через старый Apps Script, чтобы таблица продолжала пополняться);
   - сообщение в Telegram-канал с именем, телефоном, городом, меткой рекламы и ссылкой «Написать в WhatsApp».
   - сделку в Битрикс24 (основная воронка, этап «Новая») с контактом по телефону.
   Если таблица, Telegram или Битрикс недоступны, отправка повторяется автоматически.
4. Страница показывает «Спасибо» и открывает WhatsApp-чат с менеджером (+7 707 231 4955),
   в котором уже набраны имя, город и телефон. Человеку остаётся нажать «Отправить».

Защита формы: скрытое поле от ботов, не больше 5 заявок с одного адреса за 10 минут,
повтор того же телефона в течение 2 минут не создаёт дубль.

## Как обновить страницу на airl.kz

1. При необходимости заменить фото в `hq/assets/` (имя файла как в `site/assets/`) или скачать
   свежую страницу с Firebase (Actions → «Copy live page into site/»). Если кто-то правил
   `ai-for-work/workshop/index.html` прямо в `landing` (например, добавил счётчик), сначала
   перенести эту правку сюда (в `airl-head.html`), иначе следующая сборка её затрёт.
2. `./build-airl.sh`
3. Скопировать `dist/airl/` в репозиторий `aza9908/landing` как `ai-for-work/workshop/`
   (старую папку заменить целиком), закоммитить и запушить в `main`. Firebase App Hosting
   опубликует за несколько минут. Остальные файлы сайта при этом не меняются.

## Установка и обновление на сервере

С компьютера:

```
scp install.sh root@89.35.124.238:/root/
ssh root@89.35.124.238
bash install.sh --domain server.airl.kz --whatsapp 77072314955 --telegram --page-url https://airl.kz/ai-for-work/workshop/
```

Скрипт можно запускать повторно: заявки, пароль админки и настройки сохраняются, перед
обновлением делается бэкап базы. Номер WhatsApp и канал Telegram запоминаются, при
следующих запусках флаги можно не указывать.

На сервере с nginx страница добавляется отдельным сайтом в
`/etc/nginx/sites-available/airl-workshop.conf`. Конфиг проверяется `nginx -t`; при ошибке
он откатывается, а остальные сайты не затрагиваются. Сертификат Let's Encrypt выпускает
certbot, продление автоматическое. На сервере без nginx ставится Caddy.

Флаги:

| Флаг | Что делает |
|---|---|
| `--domain NAME` | домен с HTTPS (A-запись должна указывать на сервер) |
| `--whatsapp NUM` / `--no-whatsapp` | номер менеджера для шага WhatsApp после формы / выключить |
| `--telegram` / `--no-telegram` | подключить Telegram-канал (скрипт спросит токен бота) / отключить |
| `--bitrix` / `--no-bitrix` | создавать сделки в Битрикс24 (скрипт спросит адрес вебхука, ввод скрыт) / отключить |
| `--forward` / `--no-forward` | включить / выключить копию заявок в Google Sheet |
| `--page-url URL` | страница живёт по другому адресу: посетители сервера уходят туда (с UTM), `/api` и `/admin` работают как раньше |
| `--serve-page` | снова отдавать страницу с этого сервера (отменяет `--page-url`) |
| `--refresh-site` | заново скачать страницу с airl-workshop.web.app |
| `--from-dir PATH` | взять страницу из локальной папки (например, `site/` из этого репозитория) |

### Telegram

1. В @BotFather: `/newbot`, получить токен.
2. Добавить бота в канал или группу администратором (в канале: с правом публикации).
3. На сервере: `bash install.sh --telegram`. Скрипт спросит токен (ввод скрыт) и канал или
   группу (`@имя`, ссылку `t.me/...` или Enter для закрытых: тогда нужно опубликовать там
   любое сообщение, и скрипт найдёт чат сам) и пришлёт туда тестовое сообщение.

Токен хранится только на сервере, в `/etc/airl-workshop.env`. В репозиторий его не добавлять.

## Команды на сервере

```
airl-workshop stats            # сколько заявок, сколько доставлено в таблицу и Telegram
airl-workshop telegram-test    # тестовое сообщение в канал
airl-workshop backup           # бэкап базы прямо сейчас (ежедневный идёт сам в 03:30)
airl-workshop import file.csv  # загрузить старые заявки, например выгрузку Google-таблицы
journalctl -u airl-workshop -f # логи бэкенда
systemctl restart airl-workshop
```

Настройки лежат в `/etc/airl-workshop.env`. После правки: `systemctl restart airl-workshop`.

## Как поменять страницу

- Если страницу поменяли и задеплоили на Firebase: на сервере `bash install.sh --refresh-site`.
- Если правите файлы в `site/` здесь: скопируйте папку на сервер и запустите
  `bash install.sh --from-dir /root/site`.

## GitHub Action

`.github/workflows/mirror-site.yml` скачивает страницу с airl-workshop.web.app в `site/` и
коммитит изменения. Запускается при изменении самого workflow или `app/sitetool.py`, а
также вручную: вкладка Actions → «Copy live page into site/» → Run workflow.
